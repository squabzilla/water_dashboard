**Project: Calgary Water Main GIS Dashboard**
A web-based GIS dashboard exploring water main incidents in Calgary. Tech stack: FastAPI (Python) backend, MapLibre + React/TypeScript frontend, PostGIS database running in a Podman container.

**Infrastructure (complete):**
- Single Podman container running `docker.io/postgis/postgis:16-3.5` (named `postgres`), managed by Podman Quadlets via systemd
- Container exposes PostGIS on `127.0.0.1:5433` (external) / `5432` (internal) — bound to loopback only, not publicly accessible
- Persistent data stored in a named Podman volume (`postgres-data`), managed separately from the project folder
- Credentials stored in `~/.config/water_dashboard/.env`, never in the repo — `.env.example` documents required variables (`POSTGRES_USER`, `POSTGRES_PASSWORD`)
- Quadlet files live in `database/quadlets/` in the repo: `postgres.container` and `postgres-data.volume`
- `deploy.sh` symlinks Quadlet files into `~/.config/containers/systemd/`, validates `.env`, and starts the service — idempotent, safe to re-run for updates
- `stop_deployment.sh` stops the service and disables boot persistence while preserving volume data and symlinks
- WSL2 on Windows with systemd enabled — requires `PodmanArgs=--cgroups=enabled --log-driver=journald` in `postgres.container` to work around WSL2's cgroup v1 default
- pgAdmin not containerized — connect via Windows-side pgAdmin or psql directly to `localhost:5433`
- Python package manager is `uv`, Node manager is `fnm`
- Intended production deployment: DigitalOcean Droplet (raw Linux VM), same Quadlet setup, with `sudo loginctl enable-linger $USER` for boot persistence

**Database (complete):**
- Database named `calgary_watermains`, created automatically by the `postgis/postgis` image on first run
- PostGIS 3.5.2 initialized automatically, confirmed: `postgis`, `postgis_topology`, `postgis_tiger_geocoder`, `fuzzystrmatch`, `plpgsql` all present
