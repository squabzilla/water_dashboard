Dependencies between layers
**************************************************************************************************************

page component              shows data; filters arrive as props (from the URL once the router exists)
  → useCurrentLocation.ts       what URL are we on?                           (router step)
  → urlStateSchemas.ts          are these query parameters valid?             (deferred)
  → useApiRequest.ts            loading / error / data, cancels stale requests (extracted later)
      → apiEndpoints.ts             what can I ask for?
          → fetchValidatedJson.ts       how do I ask, and check the answer?
              → apiSchemas.ts               what does a valid answer look like?
              → apiErrors.ts                how do I describe a failure?
              → apiConfig.ts                where does the API live?

component → navigation.ts       change page (pushState) or change filters (replaceState)
                                 → notifies useCurrentLocation.ts

App.tsx   → routeConfig.ts      which page component matches this path?

**************************************************************************************************************
Decisions made
**************************************************************************************************************
 
Dev / API connection:
    Vite dev proxy forwards /api to FastAPI (127.0.0.1:8000); frontend uses relative URLs.
 
Page switching:
    Hand-written History API router, no router library. Paths pick the page, query string holds filters.
    pushState for page changes, replaceState for filter changes. Bookmarkable URLs, no reload on filter change.
 
Loading and error state:
    Small hand-written hook (useApiRequest), no TanStack Query.
 
Charts:
    Drawn in the browser with Chart.js (one runtime dependency). Not generated by Python or R.
    R may be revisited for the deferred Precipitation/Breaks and Temperature/Breaks pages
    (pre-rendered static figures, kept out of the request path).
 
Map layer loading:
    Plain GeoJSON first. Vector tiles (PostGIS ST_AsMVT through a FastAPI endpoint) expected to be needed
    for watermain_pipes; decide after measuring payload size and map smoothness.
    GeoJSON fetchers would join apiEndpoints.ts, with looser validation than the summary endpoints get.
 
API data validation:
    Zod schemas check every API response at the boundary; types are derived from the schemas.
 
Dependencies:
    Avoid where practical; measure the tree with npm ls --all before and after adding packages.
